Larmor

A digital twin that decides how far new scan evidence may move its belief.

Open the twin Open the test bench Slides

The question

0.69 → 0.85
  1. One number rose between two brain scans taken six months apart. It is Cho/Cr: choline divided by creatine, two molecules measured in one small cube of tissue.
  2. The second scan was worse. Its peaks were broader and it had more noise.
  3. So the twin moves a third of the way, to 0.741 ± 0.048, and asks for a repeat scan.

Try it in five steps

  1. 1

    Twin state

    Press Start empty, then Next packet six times. A packet is one measured value with its uncertainty, its quality checks and its source file. The belief builds one packet at a time.

    Now drag the WARN policy slider to ×1. Cho/Cr jumps to 0.768. That is what the twin would believe if it took the worse scan at full weight.

  2. 2

    Check a packet

    Pick a packet from the list and read the decision on the right.

    • E-t1-chobadRejectRejected for 9 reasons.
    • U05WarningThe producer says PASS. Its own signal-to-noise check fails, so the twin uses WARN.
    • U13RejectA scan from a 1.5 T scanner. It cannot be compared with the 3 T baseline.
  3. 3

    Trace to source

    Click a box. Every value walks back to its file and to the file's fingerprint (SHA-256).

  4. 4

    Competing explanations, then What to measure next

    The first screen lists what else could explain the rise, and the test that would settle each one.

    The second gives the advice: re-shim (make the magnetic field more even) and repeat the scan. It takes 4.1 minutes. If nothing changed, a clean repeat should land between 0.61 and 0.88.

  5. 5

    Test bench

    250 simulated follow-up scans where we know the answer, so the twin can be graded.

    93 %of error bars hold the true value
    ×1.4warning factor measured, against the ×2 we declared
    3 %of no-change cases where the twin claimed a change

What the online copy cannot do

It is read-only. It shows stored packets and one stored bench run. To check a packet of your own or run a new bench, run Larmor on your own computer.

Run it yourself

  1. Install Python 3.11 and get the code from the repository.
  2. Install the packages: 
    pip install -r requirements.txt
  3. Get the organizers' StarterPack v0.3. It is not in this repository. Put the folder MRI_Hackathon_DataScience_StarterPack_v0.3 next to the twin folder, or point the environment variable NMR_STARTERPACK at it.
  4. Start the app from the repository folder, then open http://localhost:8765: 
    py -m uvicorn server:app --app-dir twin --port 8765

    On macOS or Linux, write python in place of py.

Felix, the help assistant, is optional. It needs a language model running on your own machine with an OpenAI-style API. Point LARMOR_LLM_BASE_URL and LARMOR_LLM_MODEL at it. With no model, set LARMOR_ASSISTANT_WARM=0 and everything else works as before.

Limits

  • The data are synthetic. They come from the organizers' StarterPack for the InnovateU NMR challenge "From Spins to a Health Digital Twin" (Ulm, 21 Nov 2026).
  • One subject, two sessions.
  • No clinical meaning. The twin advises what to measure next and never names a diagnosis.
  • The drift we allow over six months is a teaching assumption.
